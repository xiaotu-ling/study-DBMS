一.约束概述
      1.为什么需要约束
         ==数据完整性==是指==数据的精确性==和==可靠性==. 它是==防止==数据库中==存在不符合语义规定的数据==和==防止因错误信息==的输入==造成无效操作==或==错误信息==而提出的.
         -->
         为了实现完整性,SQL就以约束的方式对表里的数据进行额外的条件限制:
             1.1 实体完整性: 同一个表中,不能同时存在两条完全相同无法区分的记录.
             1.2 域完整性: 例如:年龄范围0-120, 性别范围"男/女"等等
             1.3 引用完整性: 例如员工所在部门要在部门表里能够找到
             1.4 用户自定义完整性: 例如:用户名唯一,密码不能为空等,本部门经理的工资不得超过本部门职工的平均工资的5倍.
      2.什么叫约束: 对表中字段的限制
      3.约束的分类 :
         3.1 从约束的==字段个数==来区分
             ①==单列==约束
             ②==多列==约束
         3.2 从约束的==作用范围==来区分
             ①==列级==约束: 声明约束声明在对应字段后面
             ②==表级==约束: 在表中所有字段声明完以后,在所有字段的后面声明约束
         3.3 从约束的==作用(功能)==来区分
             ①==not null== (非空约束)
             ②==unique== (唯一性约束)
             ③==primary key== (主键约束)
             ④==foreign key== (外键约束)
             ⑤==check== (检查约束)
             ⑥==default== (默认值约束)
         3.4 ==如何添加==约束来区分
             ①==CREATE TABLE== 时添加约束
             ②==ALTER TABLE== 时添加 / 删除约束

	  6.唯一性约束:unique
	     用来限制某个字段/某列不能重复
	     ==在CREATE TABLE时添加唯一性约束==
	        CREATE TABLE test2(
            id INT UNIQUE # 列级约束,
            last_name VARCHAR(25),
            email VARCHAR(25),
            salary DECIMAL(10,2),
            CONSTRAINT uk_test2_email UNIQUE(email) # 表级约束
            );
            ==uk_test2_email==是给这个约束起的名字,后面删除约束等操作都需要约束名,不起名==可以直接写UNIQUE(email)==,这样==约束名就是email==.
            SELECT * FROM information_schema.table_constraints
