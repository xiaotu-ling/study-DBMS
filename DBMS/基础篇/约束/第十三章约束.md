一.约束概述
      1.为什么需要约束
         ==数据完整性==是指==数据的精确性==和==可靠性==. 它是==防止==数据库中==存在不符合语义规定的数据==和==防止因错误信息==的输入==造成无效操作==或==错误信息==而提出的.
         -->
         为了实现完整性,SQL就以约束的方式对表里的数据进行额外的条件限制:
             1.1 实体完整性: 同一个表中,不能同时存在两条完全相同无法区分的记录.
             1.2 域完整性: 例如:年龄范围0-120, 性别范围"男/女"等等
             1.3 引用完整性: 例如员工所在部门要在部门表里能够找到
             1.4 用户自定义完整性: 例如:用户名唯一,密码不能为空等,本部门经理的工资不得超过本部门职工的平均工资的5倍.
      2.什么叫约束: 对表中字段的限制
      3.约束的分类 :
         3.1 从约束的==字段个数==来区分
             ①==单列==约束
             ②==多列==约束
         3.2 从约束的==作用范围==来区分
             ①==列级==约束: 声明约束声明在对应字段后面
             ②==表级==约束: 在表中所有字段声明完以后,在所有字段的后面声明约束
         3.3 从约束的==作用(功能)==来区分
             ①==not null== (非空约束)
             ②==unique== (唯一性约束)
             ③==primary key== (主键约束)
             ④==foreign key== (外键约束)
             ⑤==check== (检查约束)
             ⑥==default== (默认值约束)
         3.4 ==如何添加==约束来区分
             ①==CREATE TABLE== 时添加约束
             ②==ALTER TABLE== 时添加 / 删除约束

          SELECT * FROM information_schema.table_constraints
          WHERE table_name = '表名称';

三.唯一性约束:unique
	     用来限制某个字段/某列不能重复
	添加唯一性约束
	     ==在CREATE TABLE时添加唯一性约束==
	        CREATE TABLE test2(
            id INT UNIQUE # 列级约束,
            last_name VARCHAR(25),
            email VARCHAR(25),
            salary DECIMAL(10,2),
            CONSTRAINT uk_test2_email UNIQUE(email) # 表级约束
            );
            ==uk_test2_email==是给这个约束起的名字,后面删除约束等操作都需要约束名,不起名==可以直接写UNIQUE(email)==,这样==约束名就是email==.
            SELECT * FROM information_schema.table_constraints
            WHERE table_name = 'test2';
             ![[Pasted image 20260805163244.png]]
             ![[Pasted image 20260805162739.png]]
            可以向声明为UNIQUE的字段添加NULl值,并且可以多行重复都是NULL值.
         ==在ALTER TABLE==时添加唯一性约束,但如果改之前有重复的内容,会添加失败.
             ALTER TABLE test2
             ADD UNIQUE(last_name);
             以及
             ALTER TABLE test2
             MODIFY salary DECIMAL(10,2) UNIQUE;
         ==复合的唯一性约束==:
             CREATE TABLE USER(
             id INT,
             NAME VARCHAR(15),
             PASSWORD VARCHAR(25),
             CONSTRAINT uk_USER_name_pwd UNIQUE(NAME,PASSWORD)
             );
             只要==被复合==附加唯一性约束的几个字段==不完全一样==,==就可以添加==成功.例如上述例子中,先添加(1,'TOM','111'),后面可以再添加(1,'TOM1','111'),(1,'TOM','112')等等,==只要不是==NAME和PASSWORD两个==都一样就可以添加成功==.
    删除唯一性约束
         7.1: 添加唯一性约束的列上也会自动创建唯一索引
         7.2: 删除唯一约束只能通过删除唯一索引的方式删除
         7.3: 删除时需要指定唯一索引名,唯一索引名就和唯一约束名一样
         7.4: 如果创建唯一约束时未指定名称,如果是单列,就默认和列名一样;如果是组合列,就默认和()中排第一个的列名相同. 也可以自定义唯一性约束名.

四.主键约束: 用来唯一标识表中的一行记录
     关键字:primary key --> 相当于唯一性约束和非空约束的组合.
     1.概述
         1.1 ==一个表==最多只能有==一个主键约束==,可以在列级创建,也可以在表级创建
         1.2 主键约束对应着表中的一列或者多列(复合主键)
         1.3 如果是多列组合的==复合主键约束==,那么这些==列都不允许为空==,并且==组合的值不能重复==.
         1.4 ==MySQL的主键名是PRIMARY==,就算自己命名了主键约束命也没用.
         1.5 当==创建主键约束==时,系统就会==默认==在所在列或列组合上==建立对应的主键索引==.如果==删除主键约束==了,主键约束对==应的索引就自动删除==了.
         1.6 需要注意,==不要修改主键字段的值==.因为主键是数据记录的唯一标识,如果修改了主键的值,就有可能会破坏数据的完整性.
    2.添加约束
        ==在CREATE TABLE时添加约束==:
             CREATE TABLE test3(
             id INT PRIMARY KEY, --> 列级约束
             last_name VARCHAR(15),
             salary DECIMAL(10,2),
             email VARCHAR(25)
             # CONSTRAINT pk_test3_id PRIMARY KEY(id) --> 表级约束
             上面虽然主键约束起了名叫pk_test3_id,但是查询主键约束名==还是叫PRIMARY==,所以没必要起名字.
             );
             ![[Pasted image 20260805172742.png]]
             CREATE TABLE test4(
             id INT ,
             name VARCHAR(15),
             PASSWORD VARCHAR(25),
             PRIMARY KEY(NAME,PASSWORD) --> 符合主键约束
             );
        ==在ALTER TABLE时添加约束==:
             CREATE TABLE test5(
             id INT,
             last_name VARCHAR(15),
             salary DECIMAL(10,2),
             email VARCHAR(25)
             );
             ALTER TABLE test5
             ADD PRIMARY KEY (id);
    3.删除主键约束:ALTER TABLE test5 DROP PRIMARY KEY;
五.自增列:AUTO_INCREMENT
     作用:让某个字段的值自增
     关键字:auto_increment
     特点和要求:
         1.==一个表==最多只能有==一个自增长列==
         2.当需要产生唯一标识符或顺序值时,可设置自增长
         3.自增长列==约束的必须是键列==(主键列或者唯一键列)-->PRIMARY KEY 或者UNIQUE 
         4.自增约束的列的数据类型==必须是整数类型==
         5.如果自增列指定了0和null,会在当前最大值的基础上自增 ; 如果自增列手动指定了具体值,直接赋值为具体值. --> 例如==现在有五条==记录,==id列是主键==,现在==添加==新一列==(0,name)或者(NULL,name)==,==添加==会==成功==,==但==是==id==编号==为六==.指明id为10则会添加id为10的一列
         ==例子==:
             CREATE TABLE table1(
             id INT auto_increment,
             name VARCHAR(15)
             );
             --> ==报错!== , 因为id虽然是整数类型,但不是主键,没有主键约束.
             应该是:
             CREATE TABLE table1(
             id INT PRIMARY KEY auto_increment,
             name VARCHAR(15)
             );
         开发中,一旦主键作用的字段上声明有AUTO_INCREMENT , 则我们在==添加数据时==,就==不要给主键对应的字段去赋值==了,让其自增.
     在创建表时声明AUTO_INCREMENT或者在ALTER TABLE时给主键或者唯一键去添加AUTO_INCREMENT .
         CREATE TABLE test7(
         id INT PRIMARY KEY AUTO_INCREMENT,
         name VARCHAR(25)
         );
         ==或者==
         CREATE TABLE test7(
         id INT PRIMARY KEY,
         name VARCHAR(25)
         );
         ALTER TABLE test7
         MODIFY id INT AUTO_INCREMENT
     删除:
         ALTER TABLE test7
         MODIFY id INT ;
六.MySQL8.0数据自增的持久性
     MySQL5.7中:
         CREATE TABLE test9(
         id INT PRIMARY KEY AUTO_INCREMENT
         );
         然后==添加数据==:
         INSERT INTO test9
         VALUES(0),(0),(0),(0);
         这样就添加了==id1,2,3,4==.
         现在我们==删除一条==:
         DELETE FROM test9
         WHERE id = ==4==;
         然后==再添加==数据:
         INSERT INTO test9
         VALUES(0);
         添加的数据==id为5而不是4==(但是如果是==重启服务器==后再添加则==会接着3自增==,为4)
    在MySQL8.0中,如果删除了一条数据(例如上面的id),则是不会接着上面的id自增,哪怕需要重启服务器也不会,删掉4,添加一个新的也会是5而不是4.-->不管重不重启服务器,id的==自增是持久的==,删掉id=4之后,添加一条新的记录就是5而不会是4.
七外键约束:FOREIGN KEY
     作用:限定某个表的某个字段的==引用完整性== . 
     例如:员工表的员工所在部门的选择,必须在部门表能找到对应的部分
     ![[Pasted image 20260807140614.png|575]]
     特点:
         1.==从表==的外键列,必须引用主表的主键或者唯一约束的列
         2.在创建外键约束时,如果不给外键约束命名,==默认名不是列名,而是自动生成一个外键名==,也可以指定外键约束名.
         3.==创建==表时就指定外键约束的话,要==先有==参考的==主表==,==才能创建从表==.
         4.==删表==时,==先删从表==,==再删主表==
         5.当主表的记录被从表参照时,主表的记录将不允许被删除,如果要删,必须先删除从表中依赖(引用)该记录的数据,然后才可以删除主表的数据
         6.在从表中指定外键约束,而且一个表可以建立多个外键约束
         7.从表的外键列与主表被引用的列的==名字可以不一样==,但是==数据类型必须一样==,==逻辑意义一致==.
         8.==当创建外键约束时,系统默认会在所在列上建立对应的普通索引==.但是,索引名是列名,不是外键的约束名
         9.删除外键约束后,==还需要手动删除对应的索引==.

        4.约束等级:
             ==Cascade方式== : 在父表上进行update / delete 记录时,同步update / delete 掉子表的匹配记录
             ==Set null方式== : 在父表上进行update / delete 记录时,将子表上匹配的记录的列设为null,注意此时子表的外键列不能为not null
             ==No action方式== : 如果子表中有匹配的记录,则不允许对父表对应候选键进行 update / delete 操作.
             ==Restrict方式== : 同 No action,都是立即检查外键约束.
             ==Set default方式== : 父表有变更时,子表将外键列设置成一个默认值,但Innodb不能识别.
