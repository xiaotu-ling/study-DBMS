一.基础知识
     ==存储数据是处理数据的第一步==.
     存储数据的过程:==创建数据库== -> ==确认字段== -> ==创建数据表== -> ==插入数据==
     数据库标识符命名规则:
        ① ==数据库名==,==表名==不得超过==30个字符==,==变量名==不得超过==29个字符==.
        ② 必须只包含 ==A-Z==,==a-z==,==0-9==, _ 共63个字符.
        ③ 数据库名,表名,字段名(也就是列名)等对象的==名称中间不能有空格==.
        ④ ==同一==个MySQL==软件==里,==数据库不能同名==,==同一库==中,==表不能同名==,==同一表==中,==字段不能同名==.
        ⑤ ==保证字段名和类型的一致性==:假如数据类型在一个表里是整数,在另一个表里别变成别的类型了.

    3.DCL中COMMIT和ROLLBACK
         ①COMMIT:提交数据,==一旦执行==,则数据就被==永久保存==在了数据库中,意味着数据==不能被回滚==.
         ②ROLLBACK:回滚数据.==一旦执行==,则可以==实现==数据的==回滚==.==回滚到最近的一次COMMIT之后==. -> 可以实现不一定成功.
    4.比较 TRUNCATE TABLE 和DELETE FROM 
        ①相同点:都可以实现对表中的所有数据进行删除,并保留表结构
        ②不同点:
        TRUNCATE TABLE:一旦执行,表数据全部清除.同时==数据不可以回滚==.
        DELETE FROM:一旦执行,表数据可以全部清除.同时==数据可以回滚==.
    5.DDL(数据定义语言)和DML(数据操作语言)
         ①:==DDL的操作==一旦执行,就==不可回滚====,执行DDL之后自动进行一次COMMIT,不能回滚.
         ②DML的操作==默认情况==一旦执行也==不可以回滚 ==,但是如果在==执行DML之前==,==执行==了 ==SET autocommit = FALSE==,则执行的DML操作可以实现回滚.
         SET autocommit一般是等于TRUE,也就是执行DML之后自动提交就不能回滚了,我们改为FALSE就可以回滚了.

四.阿里巴巴Java开发手册之MySQL字段命名
     ==1==.表名,字段名必须用小写字母或数字,禁止出现数字开头,禁止两个下划线中间只出现数字.
     ==2==.禁止使用保留字.
     ==3==.表必备三字段:id,gmt_creat,gmt_modified.其中id必为主键,类型为BIGINT UNSIGNED,单表时自增,步长为一.剩余两个均为DATETIME类型,前者表示主动式创建,后者表示被动式更新.
     ==4==.表的命名最好是遵循"业务名称_表的作用".
     ==5==.库名与应用名称尽量一致.
五.MySQL8.0新特性
     例如:我现在创建一个表book1
        CREATE TABLE IF NOT EXISTS book1(
        id,INT
        book_name,VARCHAR(255)
        );
        然后执行删除命令
        DROP TABLE book1,book2;
        如果是==MySQL5.7==,则会==报错显示没有book2==,==但是删掉了book1==,在==MySQL8.0==则是只有==成功和回滚==两个结果,也就是==不成功就回滚==,在上面例子就是删除失败,book1依旧存在.要么都成功,要么都不成功.
        ->==把事务整体原子化==,一起完成或者失败,不会只完成前面一部分而后面失败.
