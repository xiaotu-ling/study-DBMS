一.多表查询
     1.==为什么要有多表查询==
        实际数据库是有多个表的，所以需要多表查询，前提是多个表之间有关系（一对多，一对一等等）。
        例如现在示例数据库中有employees表，departments表，locations表
         ![[屏幕截图 2026-06-04 195514.png]]
        他们之间有联系：==employees表==里有==employee_id==,==department_id==，==departments表==里有==department_id==,==location_id==,而==locations==表里有==location_id==。
        例如：
        我想查询名为'Abel'的员工在哪个城市工作？
        正常应该是先查employees表看他的部门号，然后通过departments表看他的地区号，最后通过lacations表看具体位置信息。==要查三次单表查询==。
     2.==多表查询如何实现==
        现在要：
        SELECT employee_id,department_id,department_name
        FROM employees,departments;
        这样查==2889条记录==，可==员工才有107人==，明显错误。
        员工有==107==个人，部门有==27==个，相乘刚好==2889==，每个员工都和每个部门匹配一遍，出现了==笛卡尔积的错误==。
        ==***笛卡尔积***==
         ![[Pasted image 20260604200106.png]]
        错误原因：缺少了连接多表的条件。
     3.==多表查询的正确方式：==
        要有==连接条件==：
        WHERE employees.department_id = departments.department_id
        也就是：
        SELECT employee_id,department_name
        FROM employees,departments
        WHERE employees.department_id = departments.department_id;
         ![[屏幕截图 2026-06-04 201159.png|143]]
         ![[屏幕截图 2026-06-04 201208.png]]
     4.==拓展==：
        SELECT employee_id,department_name,==department_id==
        FROM employees,departments
        WHERE employees.department_id = departments.department_id;
        这样会报错，会提示你要查询的department_id不明确，因为没说是那个表的。
        SELECT employee_id,department_name,==employees.department_id==
        FROM employees,departments
        WHERE employees.department_id = departments.department_id;
        ==如果查询语句中出现了多个表中都存在的字段，则必须指明该字段所在的表==
        建议：多表查询时每个字段前==都指明==查询字段来自的==表==。
     5.注意到多表查询要频繁注明字段以及来自于那个表，很长一段影响阅读，可以在==FROM==语句中==给表起别名==，在==SELECT==和==WHERE==中==使用别名==。
        SELECT emp.employee_id,dept.department_name,==dept.department_id==
        FROM employees emp,departments dept
        WHERE emp.department_id = dept.department_id;
        ![[屏幕截图 2026-06-04 202930.png]]
        注意：如果==给表改了别名就只能用别名==，不能改了别名还用departments.department_id这种原名。
     6.==小练习：查询员工employee_id,last_name,department_name,city。==
         SELECT emp.employee_id,emp.last_name,dept.department_name,loc.city
         FROM employees emp,departments dept,locations loc
         WHERE emp.department_id = dept.department_id AND dept.location_id = loc.location_id;

        ==如果有n个表实现多表查询，则需要至少n-1个连接条件。==
     7.==从宏观看多表查询：多表查询的分类==
         ①等值连接与非等值连接（针对连接条件）
             一个非等值连接的例子：
             SELECT *
             FROM job_grades; 
             ![[屏幕截图 2026-06-04 204745.png|225]]
             ==现在查询每个员工的姓名，工资还有grade_level==
             SELECT emp.last_name,emp.salary,gra.grade_level
             FROM employees emp,job_grades gra
             ==WHERE emp.salary BETWEEN gra.lowest_sal AND gra.highest_sal;==
             ![[屏幕截图 2026-06-04 205244.png]]
         ②自连接与非自连接
             上述例子都是非自连接。
             自连接：employees表里有employee_id和manager_id。后者也是公司员工。
             例子：查询员工id，员工姓名及其管理者的id和姓名
             SELECT emp1.employee_id,emp1.last_name,emp2.manager_id,emp2.last_name
             FROM employees emp1,employees emp2
             WHERE emp1.manager_id = emp2.employee_id;
             ==第一个表获取employee的信息，用第一个表的二employee的对应manager_id去查第二个表manager的具体信息，相当于第一个表只获取了employee的信息以及对应的管理者的id，用这个id去第二个表里查具体是哪个员工以及其信息。==
         ③内连接与外连接
             内连接：==合并具有同一列的两个以上的表的行，结果集之中不包括一个表与另一个表不匹配的行。==
                SELECT employee_id,department_name
                FROM employees,departments
                WHERE employees.department_id = departments.department_id;
                这个查询结果有106条，但是员工有107个人，因为有一个员工没有部门号，这个查询==只把满足WHERE条件==的查询出来了。
             外连接：==合并具有同一列的两个以上的表的行，结果集之中除了包括一个表与另一个表不匹配的行之外，还查询到了左表或者右表中不匹配的行。==
                 所以外连接分为==左外连接==，==右外连接==，==满外连接==
                 1）左外连接：两个表在连接过程中除了返回满足连接条件的行以外==还返回== ==左表==中不满足条件的行，这种外连接叫做==左外连接==，左外连接连接条件左边的是==主表==，右边是==从表==。
                 2）右外连接：两个表在连接过程中除了返回满足连接条件的行以外==还返回== ==右表==中不满足条件的行，这种外连接叫做==右外连接==，右外连接连接条件右边的是==主表==，左边是==从表==。
                 ==外连接练习==：
                A.SQL92语法：
                    查询==所有==员工的last_name,department_name信息
                    ==SQL92语法实现内连接==：见上。
                    ==SQL92语法实现外连接==：左表和右表相当于两条腿，它们不一样长：
                    SELECT employee_id,department_name
                    FROM employees,departments
                    WHERE employees.department_id = departments.department_id;
                    在这个例子中，员工表有一个员工部门号是NULL导致没法查询其部门，也就是==employees表多==，那么在这个例子中就使用==左外查询==。
                    SQL92实现外连接==对从表是使用（+）==：
                    SELECT employee_id,department_name
                    FROM employees,departments
                    WHERE employees.department_id = departments.department_id(+);
                    ==但是MYSQL不支持SQL92的外连接的写法，所以会报错==，ORACLE可以使用该写法。

                    ==UNION的使用==:
                     利用==UNION关键字==，可以给出多条SELECT语句，并将它们的结果==组合成单个结果集==。合并时，==两个表对应的列数和数据集类型必须相同==，并且相互对应。各个SELECT语句之间使用==UNION==或者==UNION ALL==关键字==分隔==。
                        ==UNION操作符==：完整的B加上不包含的A
                        ![[Pasted image 20260605103435.png]]
                        ==UNION ALL操作符==：A加上B
                        ![[Pasted image 20260605103525.png]]
                        例如在我们的例子中：employees表和departments表共有106个员工信息，employees表单独有一个员工没部门号，departments表中有16个部门没有员工。
                        那么==UNION是1+106+16==
                        ==UNION ALL是1+106+106+16==
                     UNION：会执行去重操作
                     UNION ALL：不会执行去重操作
                     结论：如果明确知道合并后数据结果不存在重复数据，尽量使用UNION ALL。
