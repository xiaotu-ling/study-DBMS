==下面两个没有什么必然关系，只是放在一起学习。==
一.排序
        ①SELECT * FROM employees;
        这个查询每次的结果都是一样的，==默认情况==下查询返回数据是==按照添加数据的顺序显示的==。
        ==练习：现在想按照salary从高到低的顺序显示员工顺序==
        使用==ORDER BY==对查询到的数据进行排序
        SELECT employee_id,last_name,salary
        FROM employees
        ORDER BY salary;
        ![[屏幕截图 2026-06-02 204259.png]]
        ORDER BY 默认是==从低到高==排序
        升序：ASC （ascend）
        降序：DESC （descend）
        SELECT employee_id,last_name,salary
        FROM employees
        ORDER BY salary ==DESC==;
        ![[屏幕截图 2026-06-02 204507.png]]
        ②==练习：对年基础工资总和起别名sum_salary并进行降序排序==
        SELECT employee_id,salary,salary * 12 AS "sum_salary"
        FROM employees
        ORDER BY sum_salary DESC;
        ![[{D0FEA0AE-CF08-4C3C-B964-2EE675E34F6B}.png]]
        该练习串联了前面==列别名==知识
        ③注意：列别名==只能在ORDER BY中使用==，不能在WHERE中使用。并且同时出现两者时==WHERE在FROM后，ORDER BY前。==
        ④在WHERE里不能使用列别名的原因：执行查询时==先执行FROM语句看是查询哪个表==，==然后看WHERE有什么过滤条件==，==然后看你想SELECT显示哪些列==，==最后看哪个条件是按升序/降序排列==。
        **也就是顺序是FROM employees,然后WHERE department_id IN (50,60,70)，然后SELECT salary,employee_id,最后ORDER BY department_id DESC。在执行FROM语句时还没有看见SELECT语句里的列别名，所以报错。而执行ORDER BY语句时已经执行了SELECT语句中的列别名所以不会报错。**
         ⑤当有一列升序/降序排列后，有很多重复值，例如有很多人都是100号部门的员工，那同一个部门号的这些员工怎么排序：
        ==二级排序==
        ==练习：显示员工信息，按照department_id的降序进行排列，同一部门员工按salary升序排列。==
        SELECT deparment_id,employee_id,salary,last_name
        FROM employees
        ORDER BY department_id DESC,==salary ASC==;
        ![[屏幕截图 2026-06-02 210627.png]]
        直接在部门降序排列后面将工资升序排列条件加上就行。
        注意：==多级排序==只有在==上一级排序有相同值==时才可以使用下一级的排序。
